This document explains how features for the AM1 project are created and used.

Logic behind transformations or encodings

The AM1 project is a logistic regression model that classifies questions based on the 
topics that they belong to. The topics are defined and described by CLOSER staff
on a page on their internal wiki. The raw data for the project is text that represents
question summaries, and the values for any category sets associated with questions.

A logistic regression requires numeric input features. In order to create input features
that can be used by the logistic regression model, we use the sentence-transformers model
available at https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2 to map text input
such as words, sentences and paragraphs to a 384 dimensional vector.

Source columns and dependencies

The raw input data for the AM1 project is question text summaries, and the list
of categorical values associated with a question (if there are any). For example,
the following question has the categories 'Yes'/'No' associated with it.

{
  'Summary': 'Have you looked for any kind of paid work or government training scheme
     in the last four weeks?', 
  'QuestionCategories': ['Yes', 'No'],
  'Topic': '11609' 
}

...but some questions may not have any categories associated with them, e.g. questions
where the response is a free text answer:

{
    'Summary': 'Why did you decide to leave?', 
    'QuestionCategories': [],
    'Topic': '10901'
}

The raw model question data is encoded in a JSON format similar to that shown above and 
stored in Pickle files. When training and testing models, we convert the JSON object 
representing the raw model data to a Pandas dataframe. The lists containing strings 
representing question category values are sorted, and the sorted values are concatenated 
into a single lower-case string where list elements are separated by spaces. For example, 
the question categories ['Yes', 'No'] are converted to 'no yes'.

Assumptions made during feature design

We assume that all questions have a summary associated with them. We assume that some, but not all, 
questions have categories associated with them. e.g. the 'Summary' column must have a value provided, but
null values may be permitted for the 'QuestionCategories' column in cases where a question doesn't have
categories associated with it.

We filter questions from the raw data where the question summary does not help the logistic regression
model accurately predict the topic for a question. For example, we filter questions which have summaries
that are less than N characters long and which are considered too short and uninformative. The value for 
N can vary depending on the data we are using to train/test the model.

We can also replace question category set values with null/default values if we decide that they don't 
have predictive value, e.g. they are too common or vague, such a category set containing just the words
'Yes'/'No'. We can also create a model where we filter questions which don't have categories associated
with them, or which have categories that don't have predictive value.
